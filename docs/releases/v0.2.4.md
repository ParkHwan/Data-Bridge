# Data Bridge v0.2.4 — real Confluence folder → Markdown batch ingest

> The Confluence ingest pipeline that `samples/docs/*.md` previously faked is now real code,
> merged and deployed. Revision `databridge-00008-4ww` ships the ingest **package** plus the
> **provisioning code** for a Cloud Run job that is **not yet created**; `GET /` returns 200 and the
> serving source path is unchanged (the runtime never imports the package). The **live pull demo is
> deferred** — it needs a self-authored Confluence space; internal/employer spaces are excluded by
> D-10.
> 🔗 PR [#12](https://github.com/ParkHwan/Data-Bridge/pull/12)

## 1. Why

D-6 / Phase-1 declare Confluence ingest as a must-have, but until now the corpus was six
hand-written `samples/docs/*.md` files whose frontmatter merely *mimicked* Confluence
(`source_id` / `title` / `space_key` / `breadcrumb`). v0.2.4 replaces the fake with a real pipeline:
pull every page under a configured Confluence folder over the REST v2 API, convert ADF → Markdown,
and feed the **existing** chunk → embed → pgvector path unchanged.

## 2. What shipped

- **New `src/databridge/confluence/` package** — `client.py` (async v2 subset: space /
  folder-descendants / page; httpx + tenacity; 401/429(Retry-After: numeric & HTTP-date)/4xx
  mapping; cursor pagination with a full seen-cursor cycle guard), `parser.py` (faithful
  ADF→Markdown, 25+ node types incl. tables with colspan/rowspan flattening + alignment, panels,
  media, task/decision lists, marks; fence-length-aware code; unknown nodes never drop text),
  `ancestors.py` (root→parent breadcrumb, cycle/depth/403·404 guards), `adapter.py`, `batch.py`,
  `models.py`, `exceptions.py`.
- **Re-implemented, not vendored.** Contracts were re-written in English against the sibling
  project per the CONTRIBUTING two-project rule; whole-file similarity to the reference stayed
  0.06–0.58 (boilerplate only). Crowdy is a reference, never a source of copied files.
- **Fail-safe batch** (`batch.py`): all fetch / parse / chunk / embed complete **before** the first
  store write, so a failure in those phases never touches the stored snapshot. The write phase then
  replaces sources one atomic transaction each, and garbage collection deletes vanished sources
  **only after a fully successful traversal and all writes** — it refuses to run on zero pages. A
  Postgres advisory lock keyed by `space_key`+`folder_id` keeps overlapping Cloud Scheduler runs
  from colliding. A **double empty-body guard** (adapter + batch) makes it impossible for an empty
  ADF render to wipe a stored source via `replace_source([], [])`.
- **Store additions** (`store/pg.py`): `list_source_ids` + `advisory_lock` helpers, both
  space-scoped. `replace_source` / `delete_source` bodies are unchanged.
- **Deploy wiring**: a new `confluence` extra (httpx, tenacity) installed by the Dockerfile and the
  Cloud Build gate; `scripts/setup_cicd.sh` provisions a `databridge-confluence-ingest` Cloud Run
  job (create/update), grants a dedicated scheduler SA `run.invoker`, and creates a Cloud Scheduler
  job at `0 6 * * *` Asia/Seoul. The token is a Secret Manager reference — never committed.

## 3. Verification

Offline gates, both interpreters:

- `ruff` + `mypy --strict` clean (32 source files).
- `pytest` green on **3.13** and the declared **3.12** floor (`tests/test_confluence.py`, 630
  lines: client pagination via respx, ADF fixtures/snapshots incl. the round-2 edge cases, ancestor
  cycle/403/404, adapter empty-body guard, GC ordering, `list_source_ids` + advisory lock).
- The production image builds with the `confluence` extra.

**No live Confluence pull has been run.** The live demo — the actual submission value — is deferred
until a **self-authored** Confluence space is available; an internal/employer space must never be
ingested (D-10, CONTRIBUTING). The immutable-file diff (`markdown.py`, `chunker.py`,
`replace_source` body, `runtime.py`, `citations.py`, golden set) is **zero**.

## 4. Process — 3-party review (Claude / Antigravity / Codex)

- **Design.** A 1st draft ("port the 5 sibling files by import-swap") was overturned in review:
  CONTRIBUTING is a hard rule — *re-implement contracts, never vendor* — and the repo is
  English-only. The synthesized design (16-row reconciliation) pivoted to re-implementation and
  fixed two bugs that were in the 1st draft itself: an invalid chained ADF call (corrected to the
  required two-step `parser.to_markdown(parser.parse_json(value))`), and an empty-body path that
  would have let `replace_source([], [])` delete a source.
- **Implementation, 2 rounds.** Round 1 confirmed the core safety / type / wiring invariants (the
  low 0.06–0.58 similarity supported the re-implementation; GC prepare-before-write; empty-body
  double guard; advisory-lock lifetime; env↔setup parity). Codex found **six findings — five in the
  parser** (code-fence normalization, inline-code delimiter, unknown-leaf text loss, media
  separator, table header/align/span) **plus one client cursor-cycle** gap; Round 2 fixed all six
  with fixtures, re-verified in code.
- **Reviewer-reliability note** (carried in global rules): Antigravity returned "0 issues" on each
  review it ran (the design and the round-1 implementation) while Codex's code-run findings were the
  substantive ones; verdicts were taken on Codex's findings plus owner re-measurement.

## 5. Production state

- **Merged & deployed.** PR #12 merged (`185dd3b`); the `^main$` Cloud Build ran every step —
  testdb → gates (ruff / mypy / integration) → build → push → migrate → deploy →
  `update-confluence-job` (a successful **no-op**, because the job was absent) — and rolled out
  **`databridge-00008-4ww`** (traffic 100%, image digest matching the build). Owner smoke: `GET /`
  → 200; the serving source path is unchanged because the runtime never imports the `confluence`
  package.
- **Initial job + Scheduler provisioning is manual IaC** (`setup_cicd.sh`) — Cloud Build only
  *conditionally updates the image* of an already-provisioned job, and never creates the job or the
  Scheduler. Provisioning was **held at the D-10 gate** rather than wired to a non-self-authored
  space, so no Confluence data has been ingested into prod.

## 6. Known limitations / deferred

- **Live pull demo + Scheduler provisioning** — pending a self-authored Confluence space.
- **Full re-ingest each run** (idempotent `replace_source` + GC) is the MVP; incremental sync
  (`version.number` + breadcrumb hash) is deferred.
- **Table merged cells**: Markdown cannot represent colspan/rowspan, so spans are flattened with the
  value preserved (documented in `parser.py`).
- **Page URL / version provenance** is not yet carried into `SourceDocument` / the citation
  contract (would touch immutable files); deferred by design.
