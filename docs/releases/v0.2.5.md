# Data Bridge v0.2.5 — the nightly batch survives an empty page, and the DSN leaves plaintext

> Two operational defects found by running v0.2.4 for real. A single empty Confluence page failed
> the whole nightly ingest, and the Cloud SQL DSN sat in plaintext environment variables where
> `describe` printed it. Both are fixed and deployed on revision `databridge-00014-5pp`; the live
> `/ask` path answers from the Confluence corpus with heading-anchored citations.
> 🔗 PR [#14](https://github.com/ParkHwan/Data-Bridge/pull/14) ·
> [#15](https://github.com/ParkHwan/Data-Bridge/pull/15)

## 1. Why

v0.2.4 shipped the Confluence pipeline but deferred the live pull. Provisioning it against a
self-authored space surfaced two problems the existing offline gates had not caught.

**An empty page killed the batch.** A parent page in the ingest folder had the body
`{"type":"doc","content":[{"type":"paragraph"}],"version":1}` — a title with an empty paragraph and
nothing else. `ADFParser.to_markdown` renders that to `''`, `adapter.py:26-27` raises
`EmptyBodyError`, and `batch.py` neither imported nor caught it. One such page aborted the run for
all pages.

**The database password was printed by routine commands.** `DATABRIDGE_DSN` was a plaintext env var
on the service and all three Cloud Run jobs, so any `gcloud run ... describe` emitted the full DSN.
That is how it reached a working transcript and forced a password rotation.

**The serving corpus was console-only state.** `DATABRIDGE_SPACE` is read in exactly one place
(`src/databridge/agents/deps.py:55`, default `"DEMO"`) and was written nowhere in the repository —
contradicting `setup_cicd.sh`'s own purpose of keeping infrastructure reproducible rather than
console state.

## 2. What shipped

### Empty-page skip (PR #14, `e1cd386`)

- `batch.py` catches `EmptyBodyError` around the `page_to_source_document` call **only**, logs a
  warning, and continues. `ADFParseError`, `ConfluenceAPIError`, and `BatchSafetyError` still fail
  the run.
- The skipped page's id is added to `seen`, so garbage collection **leaves its stored chunks
  alone**. Sources that genuinely vanish from the folder are still absent from `seen` and are still
  collected.
- `BatchResult.skipped_pages` (last field, defaulted) reports the count; the completion log carries
  it.
- A guard refuses collection when every page was skipped, placed before the first store write.

Preserving rather than deleting was the contested decision. `EmptyBodyError` cannot distinguish an
author-emptied page from an API response that omitted the body — `models.py:29-47` marks `body`,
`atlas_doc_format`, and `value` all optional, and `adapter.py:19-27` collapses those cases into one
exception. Deleting on that ambiguity would let a transient response destroy good chunks, and it
would reverse the contract v0.2.4 published in [§2 of its release note](v0.2.4.md): *a double
empty-body guard makes it impossible for an empty ADF render to wipe a stored source*.

### DSN via Secret Manager, serving space declared in IaC (PR #15, `f705ee2`)

- The service and all three jobs take `DATABRIDGE_DSN` from a Secret Manager reference. The
  application is unchanged — the value arrives under the same env var name.
- `setup_cicd.sh` preflights that both secrets exist **and that their `latest` version is enabled**,
  that the service exists, and that the required Confluence inputs are set — all before any Cloud
  Run resource is modified, so a missing input can no longer fail the run halfway through.
- Existing resources are converted with `--update-secrets`. **`--set-secrets` removes every other
  secret reference first**, which would have silently dropped `CONFLUENCE_API_TOKEN` from the
  nightly job.
- The Confluence job keeps `--set-env-vars` for its literal environment; after the switch both
  secret references were confirmed still present on the live job.
- **The old DSN extraction is gone.** It scraped `--format=export` for a `value:` line, which a
  `secretKeyRef` never has. Replaying that pipeline against an already-migrated variable returned
  the container image string — jobs would have been created with a garbage DSN and no error.
- `DATABRIDGE_SPACE` is now declared in `setup_cicd.sh` as `${DATABRIDGE_SPACE:=MFS}` — a default a
  caller may override, with MFS as the operational value. It is applied in the same update that
  converts the service DSN, so the switch costs one revision instead of two, and a guard skips that
  update when both are already in place.

## 3. Verification

Offline gates on `main`: `ruff` clean, `mypy` clean (32 source files), `pytest` **122 passed / 9
skipped** (baseline 119). Reproduced under the CI condition — run from outside the project root with
`PYTHONPATH` cleared — with the same result. `bash -n` clean on `setup_cicd.sh`.

**The production payload was replayed, not simulated.** The exact ADF of the page that aborted the
batch was fed through `run_confluence_batch` against a recording store:

```
BatchResult(pages=2, chunks=2, vertex_calls=2, deleted_sources=1, elapsed_seconds=…, skipped_pages=1)
events: [lock, replace:…, replace:…, list, delete:<vanished-source>, unlock]
```

Three properties at once: the run completes, the skipped page's source is **not** deleted, and a
genuinely vanished source still **is** — confirming the preservation logic did not disable garbage
collection.

**Live, after the switch:**

| Check | Result |
|---|---|
| DSN on service + 3 jobs | `secretKeyRef` on all four |
| Plaintext `postgresql://` in any resource | none |
| `CONFLUENCE_API_TOKEN` reference on the ingest job | intact |
| `GET /health` | 200 |
| `POST /ask` | answers with heading-anchored Confluence citations |
| Ingest job execution | 5 pages, 39 chunks, `skipped_pages=0` |
| Re-running `setup_cicd.sh` | `skipping update.`, revision unchanged |
| Image-only redeploy by Cloud Build | secret reference and `DATABRIDGE_SPACE` both survive |

The last two matter beyond this release. `gcloud run services update` forces a new revision whenever
a template-level flag is present, even when nothing changed, so an unguarded update would have
broken the script's documented re-run safety. And because `cloudbuild.yaml` deploys with `--image`
only, the secret wiring had to be shown to survive a normal CI deploy — otherwise every merge would
have stripped the DSN.

## 4. Process — 3-party review (Claude / Antigravity / Codex)

**Empty-page skip.** The two reviewers split on whether garbage collection should delete a skipped
page's chunks. The owner decision was to preserve, on the grounds that the shipped v0.2.4 contract
already forbids an empty render from wiping a stored source, and that the exception cannot
distinguish the two causes. Implementation review closed at zero issues in one round; it also
caught a real defect in the draft, a `logger.warning(page_id, title)` call that would treat the page
id as the format string.

**DSN / IaC.** Round 1 produced four findings: the `--set-secrets` token wipe, an unnecessarily
surrendered declarative env behaviour, a preflight that ran mid-conversion, and an asymmetric
secret-version check. The first fix round then introduced a worse defect — an idempotency guard
built on **invalid gcloud projection syntax**. It passed `bash -n`, but every invocation errored,
and under `set -euo pipefail` a failed command substitution exits, so the script would have
converted three jobs and died immediately before the service. Round 2 closed at zero blocking
issues with one low hardening item, applied in a third round.

**Lesson recorded:** `bash -n` validates shell syntax only. Commands that depend on the export
structure of deployed resources, or on gcloud projection semantics, must be verified with read-only
queries and controlled live execution — the reviewing agent's sandbox had no cloud credentials and
said so rather than asserting an unverified pass.

## 5. Production state

- Revision **`databridge-00014-5pp`**, 100% traffic, image digest `sha256:bbe503e5…`.
- The `databridge-confluence-ingest` Cloud Run job runs on the same image; Cloud Scheduler
  `0 6 * * *` Asia/Seoul, **ENABLED**.
- Serving searches a single space, set by `DATABRIDGE_SPACE`.

### Changing the serving space

Two variables are easy to confuse and do different things:

| Variable | Owner | Effect |
|---|---|---|
| `SPACE_KEY` | ingest job | the database namespace written and garbage-collected (`scripts/ingest_confluence.py`) |
| `DATABRIDGE_SPACE` | service | the search filter applied to every query (`agents/deps.py:55`) |

**To point serving at a space that is already ingested**, change the service only:

```bash
gcloud run services update databridge --project "$PROJECT" --region us-central1 \
  --update-env-vars "DATABRIDGE_SPACE=${NEW_SPACE_KEY}"
```

**To move the corpus to a different Confluence folder**, ingest first and switch serving after it
succeeds, so the service never points at an empty namespace:

```bash
gcloud scheduler jobs pause databridge-confluence-ingest \
  --project "$PROJECT" --location us-central1

gcloud run jobs update databridge-confluence-ingest \
  --project "$PROJECT" --region us-central1 \
  --update-env-vars "SPACE_KEY=${NEW_SPACE_KEY},FOLDER_ID=${NEW_FOLDER_ID}"

gcloud run jobs execute databridge-confluence-ingest \
  --project "$PROJECT" --region us-central1 --wait
# confirm pages / chunks / skipped_pages in the job log before continuing

gcloud run services update databridge --project "$PROJECT" --region us-central1 \
  --update-env-vars "DATABRIDGE_SPACE=${NEW_SPACE_KEY}"

gcloud scheduler jobs resume databridge-confluence-ingest \
  --project "$PROJECT" --location us-central1
```

Three cautions. Garbage collection is **space-wide**, so a `SPACE_KEY` that already holds another
folder's data will have that data deleted — always use a dedicated key. A space that has never been
ingested returns no results, which is why the serving switch comes last. And a permanent change
needs the `setup_cicd.sh` default updated in its own change set, or the next run of the script
restores the previous value.

## 6. Known limitations / deferred

- **Chunks of a genuinely emptied page persist.** Skipping preserves them, so a page whose author
  removed all content keeps answering from its previous text. Resolving this needs a contract change
  splitting `EmptyBodyError` into a missing-body and a rendered-empty variant, plus a delete-ratio
  guard; deliberately deferred.
- **No skip-ratio cap.** A run where one page is valid and the rest are empty still succeeds. With
  preservation this cannot cause mass deletion, which is why no threshold was invented without
  operational data to calibrate it.
- **Serving searches one space.** Multi-space retrieval was considered and cancelled; `MFS` is the
  permanent corpus.
- **Garbage collection is scoped to `space_key`, not to the folder.** Two folder batches sharing one
  space key would delete each other's sources. Not reachable today — the space holds a single
  folder — but a trap when extending.
- Carried forward from [v0.2.4](v0.2.4.md), still open: full re-ingest each run with no incremental
  sync; `colspan`/`rowspan` flattened in Markdown; page URL and version provenance absent from the
  citation contract.
